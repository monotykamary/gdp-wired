# T-14 / E-14: finite filtering before counted proof

Lane A of `MLDR-29.md`; branch `claude/mldr-gen`.

## Contract

- No protocol names, hand laws, solver changes, or budget increases in production.
- Stored-row cardinalities join the width-two zero/nonzero cube vocabulary.
- Finite filtering removes a non-caller only after an enabled machine step
  from a state satisfying the entire current family violates that law.
- Unsupported evaluations are unknown, never acceptance of a predecessor.
- All surviving laws still need ordinary checked induction.
- Other 28 candidate lists must be byte-identical to `cd0a1aa4`, three times.
- Strict original harness: `timeout -s KILL 60 ... --ms 60000`, isolated large
  VMs. Main baseline is pinned to `b788e195` until explicitly re-gated.

## Implementation

`core/count-cubes.ts` adds row-cardinality cells, not filtered quorum bodies,
which already have their own candidate families. Its atoms are state scalars,
direct field reads, and newly lifted row counts used by admitted proposals.
Each proposal is still checked against all existing small states.

`core/finite-houdini.ts` checks complete finite covers: explicit guard upper
bounds (including half-count witnesses), or direct finite-map cells with
sufficient fresh equality representatives. Other binders are unknown. It
reuses reached states and samples up to 2,000 accepted configurations, mixing
independent finite configurations with neighbors, and tries 25 requests per
state. Rejected random proposals have a fixed generic attempt cap. Each round
uses one immutable family; rounds continue until no law is removed.

The new path is gated by stored-row lifting. It does not run on the other
28 IC3Syn protocols. Existing counted allowances and the outer cooperative
wall remain unchanged. Semantic no-op transitions preserve the pre-checked
family without repeating every law evaluation.

## Reproduce on boat

All substantive work is remote. Prepare immutable data archives with git:

```sh
mkdir -p /tmp/gdp-t14-baselines
git archive b788e195 -o /tmp/gdp-t14-baselines/main.tar
git archive cd0a1aa4 -o /tmp/gdp-t14-baselines/generation.tar
supercomputer run --jobs research/track-gen/t14-verify-jobs.json \
  --out runs/t14-verify-v6 --class gate --timing --vm-type large
supercomputer run --jobs research/track-gen/t14-generation-jobs.json \
  --data /tmp/gdp-t14-baselines:baselines --out runs/t14-generation \
  --class submission --timing --vm-type large
supercomputer run --jobs research/track-gen/t14-original-jobs.json \
  --data /tmp/gdp-t14-baselines:baselines --out runs/t14-original \
  --class submission --timing --vm-type large
supercomputer run --jobs research/track-gen/t14-gate-jobs.json \
  --data /tmp/gdp-t14-baselines:baselines --out runs/t14-gate \
  --class gate --timing --vm-type large
```

One protocol/repeat per job; paired sides alternate order on the same VM.
Both archived submodule SHAs match this checkout. The pairing script copies
those exact vendor trees and installs each side outside the measured interval.
No VM-count override is used; the scheduler reuses warm capacity.

## Section 15.1

`attemptShare` in `core/support-budget.ts` divides the current remaining
allowance by the current round's untried, non-kept, non-carried laws. `join`
recomputes it before each law and removes that law from the pending set.
Ordering and `supportBudget` are unchanged. `t14-share-jobs.json` compares
this against the same E-14 source with only the round-fixed denominator
restored. The main comparison includes both changes.

## Research-only capture

`T14_CAPTURE=1` on `t14-paired.sh` enables `research/query/dump.ts` with
`DUMP_ALL=1` and the bounded transport in `t14-dump.ts`. The opt-in
`GDP_COUNTS_DUMP_ALL_PASSES=1` observes terminal SAT exits from either pass;
no proof policy changes. Selected root goals and witnesses are gzip/base64
encoded on stdout so logs remain bounded. Pre-Houdini law/count definitions
are retained for the finite Gp1 audit.

`t14-audit.ts capture.json` checks the concrete default-zero completion,
including all Gp1 laws and the machine transition. Failure of that completion
is NOT an exhaustive proof that every model completion is impossible.
`t14-replay.ts capture.json INDEX UNITS` replays the captured goal through
`grow`; UNITS must come from the original attempt's trace, not a larger budget.
