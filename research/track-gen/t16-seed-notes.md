research driver collected them from certified drops. Take only the last eight,
match the complete supplied parameter environment, and project to the exact
existing scalar/map/input-cell grid. Out-of-domain coordinates reject a seed;
there is no clamping, added map key or widened finite value set.

Snapshot vectors before callbacks can update the seed array. Try each base,
then one-coordinate neighbors, request coordinates first and round-robin across
bases. Deduplicate vectors and admit at most 256 attempts per tiny invocation:
the counter increments only after the `>=256` guard and only for a new vector.
All loops check the existing cooperative wall. Do not add time to any stage.

Candidate construction uses the existing precondition test, operation gate,
source output circuit and target tests. Seed candidates call the same existing
callback as global candidates. `finiteTinyHoudini` is unchanged: it alone can
remove a non-caller, after re-evaluating the whole current family and declared
facts and performing the actual source step. Rejected proposals cannot consume
a target. Restore default slot placeholders before ordinary DFS starts.

The research driver keeps at most eight unique consecutive witness objects
from its certified `onDrop`, so later rounds and the richer stage can reuse
those inputs. These caches are not facts or certificates and do not permit an
otherwise-invalid state. Interval pruning stays off for the next pilot.
