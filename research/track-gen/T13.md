## Reproduce on boat

Read `supercomputer --skill` first. The jobs install the frozen lockfile.
Do not run benchmarks or proof work on the laptop.

Prepare the unchanged baseline overlay with git (the only existing production
files changed by this branch are the generator and its sample-filter support):

```sh
mkdir -p /tmp/mldr-gen-baseline/core
for file in counts.ts exists.ts field-laws.ts; do
  git show "346fbcd9:core/$file" > "/tmp/mldr-gen-baseline/core/$file"
done
```

Then run:

```sh
supercomputer run --jobs research/track-gen/t13-paired-jobs.json \
  --out runs/t13-paired --class submission --timing --vm-type large \
  --data /tmp/mldr-gen-baseline:baseline
supercomputer run --jobs research/track-gen/t13-original-jobs.json \
  --out runs/t13-original --class submission --timing --vm-type large \
  --data /tmp/mldr-gen-baseline:baseline
supercomputer run --jobs research/track-gen/t13-relative-jobs.json \
  --out runs/t13-relative --class submission --timing --vm-type large
supercomputer run --jobs research/track-gen/t13-fast-jobs.json \
  --out runs/t13-fast --class interactive --timing --vm-type large
supercomputer run --jobs research/track-gen/t13-cost-jobs.json \
  --out runs/t13-cost --class submission --timing --vm-type large
supercomputer run --jobs research/track-gen/t13-gate-jobs.json \
  --out runs/t13-gates --class gate --timing --vm-type large
```

`placement.json` labels each timing claim. A `large` label does not imply that
all VMs have the same CPU model. Each baseline/candidate pair runs sequentially
on the same exclusive pinned VM; the middle pair reverses order.

## Completed receipts

The completed set uses pairs 1 and 3 from `runs/t13-paired-v3` and the retried
middle pair from `runs/t13-paired-r2-retry`. The original middle job hit its
aggregate shell deadline; its failure is retained and excluded, not relabeled.
The retry changes only the aggregate shell timeout, never a per-protocol budget.
Decode the existing receipts (no model execution) with:

```sh
bun research/track-gen/t13-report.ts runs/t13-paired-v3 \
  runs/t13-generation-summary.json runs/t13-paired-r2-retry
```

The original-harness paired results are in `runs/t13-original-v2`, bounded
relative checks in `runs/t13-relative`, the trigger census in `runs/t13-census`,
and the last type/lint/commitlint gate in `runs/t13-report-check`.

## Evidence format

- `t13-generation.ts`: no proof query; emits per-port counts, complete canonical
  lists, names, sample sizes and phase walls, compressed as `T13_DATA_GZIP_BASE64`.
  Existential caller laws remain in the canonical list, but are not incorrectly
  passed to the universal-state `trueSmall` evaluator. Witness proving is outside
  this generation-only census.
- `t13-compare.ts`: verifies zero root queries and byte-identical canonical lists
  for the other 28 protocols; emits both complete input receipts compressed as
  `T13_PAIR_GZIP_BASE64`.
- `t13-report.ts <paired-directory> <summary.json> [repeat-2-directory]`: cheap
  receipt-only decoding and SHA-256 summaries, including each source log path.
  The optional directory uses a separately retried middle pair without hiding
  its failed original receipt. No solver/model execution.
- `t13-census.ts`: cheap structural-only census; asserts that exactly one of the
  29 ports emits the new quorum or composed-row family. Its job also typechecks
  and lints the full snapshot.
- `t13-equivalence.ts`: compares generated laws with the research hand-family
  evaluators on 2,000 seeded random states and all key bindings in `{0,1,2,3}`.
  Both positive and negative instances must occur for each match. This is not a
  proof, and the oracle is not an input to production generation or proof search.
- `t13-relative.ts`: exhaustive n=3, T=2, V=2 relative-induction falsification of
  each stronger alternative added separately to the hand family. Unary/pair
  pruning uses only hand-family clauses. Post-state bounds are not truncated.
- `t13-paired.sh original`: runs the **unmodified** original `run.ts --ms 60000
  --only mldr --skip broken` twice, with trace/profiling only. It copies source to
  an isolated temporary directory and overlays the baseline files there.

The remaining `initial`, `debug`, `naive` and `pilot` job files reproduce the
investigation. Failed receipts are retained and excluded from successful gates.
Large logs and full compressed candidate archives are not committed.
