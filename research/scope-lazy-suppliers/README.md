# Lazy generated-row suppliers

## Authority and scope

Main requested this bounded successor of K `0e1758bb4141e325655d380d368b2e859dcd984b` after the combined supplier run's reported GLOBAL VM OOM. This is a source-side mitigation, not a measured memory improvement or an MLDR proof. Main authorizes one boat invocation of the existing ten tests, one additional H0/H1/t lazy control, and one focused compiler invocation. No full MLDR rerun or admission is authorized by this packet. B owns later composition under the original b036 envelope/memory 28672; the 3817 reservation-only successor remains held.

## Invariants

1. Eager dependency extraction is the 9eb `countedCertificateHyps` path, not `countedScopeHyps`. All independent-cut slices and legacy references survive. An unchecked retained offer shares its original instances/certificates; attempted reduction prunes a separate instances object only.
2. `suppliers: 'unresolved'` is explicit proposal metadata. A real reduced native receipt can mark it resolved; neither status is authority to accept a proof.
3. Only the closing adapter's **actual certificate transport decline** names a repair candidate. Missing premises, bad expansions, native-check failure, and deadline/allocator exceptions cannot request supplier repair.
4. The pass consumes `supplierRepairUsed` BEFORE calling the resolver. That flag survives repeat invocations and context withdrawal; a cancellation/refusal never renews the one repair. No producer, new search, root, lease, allowance, memory reservation or deadline is started.
5. The cold resolver uses the complete, byte-unchanged 0e generalized pair/term/naturality collector. It verifies the reconstructed full source goals match the retained source goals, retains every original premise, adds all inferred suppliers and retains original instances/certs/source goals. It clears any reduced receipt and remains unchecked. There is no truncation, initial-root cutoff or supplier-count cap.
6. The controller conservatively unions the repaired premises with its previous effective dependencies (including recipe requirements), rebuilds the relation and greatest closed held family from ALL held payloads, then invokes closing at most once more. Absent suppliers exclude the target; they are never invented or admitted. A second decline is terminal to this repair path.
7. Native final checking is unchanged. The generated collector is not called merely because a capture, reduced native check, identity check or unrelated closing step failed.

## Duplicate scan removal

`scopeCountProofPair` computes one legacy row scan, validates the offered declaration, and constructs the inferred scope from that exact scan. Its inferred proof omits offered status and declared supersets and receives no copied checked token. The new control compares serialized offered/inferred scopes against two standalone `scopeCountProof` calls. Native checking after replay is not removed.

## Existing B hard-stop prerequisite

Three files are adopted **byte-for-byte** from the already reviewed combined `bf9640f31571af0eda98e5709b5c698c9f8f9e7e`:

- `core/count-cert-transport.ts`
- `core/count-recovery/conditional-proof.ts`
- `core/work-admission.ts`

They preserve the original ledger-authenticated refusal through nested catches. K calls the existing opt-in `rethrowBudgetExpired` path; this is necessary so a swallowed resource refusal is not mistaken for a semantic transport decline. No B family-fallback or named-decline implementation is imported here. B must preserve these exact helpers when composing its diagnostics/fallback changes, and preserve K's `onTransportDecline` signal and single-repair state.

`kernel/**`, `core/count-scope-hyps.ts`, the original two test files, and the scheduler's numerical budget formulas are unchanged from K 0e. The original ten tests include direct/nested term transport, pair/duplicate/product/frame coverage and authentic legacy allocator stops.

## Additional control

`core/count-scope-lazy.test.ts` is one additional test, covering both direct and nested H0/H1/t fixtures. It checks native local certificates, zero eager generalized entries, exact instance/certificate retention, equivalent single-scan metadata, actual transport decline, full on-demand suppliers, native transport after reclosure, absent-supplier exclusion, a terminal second decline, persistent one-repair state and original hard-stop identity. Helpers in the generic controller control are explicitly opaque bookkeeping payloads: it makes no claim that the contradictory H0 source assumption is itself an inductive family theorem.

## Limitations

One declined member can still have a large full context/matrix. This change bounds how often and for how many members the generalized analysis is invoked, not its worst-case per-member memory. Source analysis predicts a reduction relative to eager capture; no RSS or OOM-causation claim is made. A new required supplier not already held can remove the target; this path deliberately does not restart search.

Validation and source receipts are separate from D source acceptance and any later Main execution schedule. No GO is implied.
