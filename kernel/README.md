# gdp-wired kernel: the prover out of the trusted base

| File | What |
| --- | --- |
| `kernel.ts` | Trusted (with `core/check.ts`). A goal is hypotheses that can't hold together. A proof is a tree of splits on linear atoms with a derivation at each leaf. The kernel reads the leaf's facts off the hypotheses under the path (ifs, mins and ∸ the path decides, conjunctions, the last disjunct still open, equal cells at keys the path proves equal, products of two rows) and asks `check.ts` whether the derivation refutes them. Two kinds of assumption: `pre` (params only: a precondition, at the start and every step) and `assume` (each request: at a step, never at the start). Every rule is a few moves of one algebra of runs (a run keeps the hypotheses met along it, each read where it was met, and the frame it ends at, every name a term over the first frame): `holds` (conditions where the run is), `reading` (a step's inputs named), `step` (a step taken from there, maps read-over-write), and a goal refuting a conclusion read at the end (`atEnd`) or across the run (`across`: plain names at the first frame, primed at the last). The induction rules: step machines (start + one step, every law in the set proven, ∀-laws instantiated at the keys the proof names), loops (invariants + a natural rank, or a tuple of ranks compared in order, that drops each turn; a rank may not read the turn's input), progress ("some request makes this happen", by naming the request and proving it allowed), step laws (`stepLawObligations`: for every allowed request, `then` relates the state before, by plain names, to the state and maps after, by primed ones, `s'` and `M'[k]`; the laws and the assumption are hypotheses, flags inlined; a history machine goes through `historyMachine`; with `steps: k`, k steps in a row, the laws and assumption before each, one `when` per step, the j-th request read as input@j), and folds over binary trees (leaf + node from both children). A leaf may use products of two rows, including earlier product rows (any degree) |
| `kernel.ts`: scope | Every name a machine, loop or fold reads is one it declares (params, inputs, state, maps, flags declared before, a law's own key); refused before any goal is made, since a goal would read a typo as one more free natural while the runtimes have no value for it |
| `kernel.ts`: histories | `historyMachine`: a machine that keeps a log of requests (`keep`, the recorded inputs read as `r.<input>`, a name prefix no other name may use). Sums are state, the sum over the log of a term of the record and params; queries are inputs, the sum over the log before the request of a term of the record, params and plain inputs; a relation `when ⇒ a ≤ b`, homogeneous over sums and queries with `when` over params and plain inputs, is proven for one record and then assumed at every step (both sides are sums over one list). `prune` adds a goal per query: a record whose order plus `after` is at most the request's adds 0, so the runtimes may drop it (they refuse requests out of order). Lean twin: `../lean-kernel/History.lean` |
| `prove.ts` | Untrusted. Grows trees: splits on whatever the hypotheses leave open, bisects bounded variables and branches on fractional coordinates when elimination is inexact, and multiplies rows when products appear (pairs of rows about the factors; degree three from rows times products of two variables; splits of a factor at zero or two factors against each other, so (x − y)² ≥ 0 becomes a product). A witness that multiplies out is a real model and stops the search. 20 s per goal, then `unknown`. `concretize` looks for a real counterexample with true arithmetic when products leave the witness abstract |
| `run-progress.ts` | No lockout and progress: in-flight requests can always complete or be admitted, and an account under every cap gets its grant. False variants get stuck |
| `run-kernel.ts` | Every earlier machine proof as kernel-checked trees, plus tampered trees the kernel must reject |
| `run-more.ts` | Termination (ranks from templates), structural induction on trees, products (monomials as atoms), and integer completeness against brute force |
| `kernel.test.ts` | Soundness fuzz, sharded by `FUZZ_SEED` (`../modal/suite.json` runs 32 seeds on Modal). Random goals with ifs, mins, ∸, products and map reads: every accepted refutation is confirmed by brute force over concrete models, emptied derivations are rejected, and no linear goal ends `unknown`. Degree three: monotone polynomials, true and false, and leaves with random products of products; nothing with a model is accepted |
| `steplaw.test.ts` | Step laws: monotone counters, a `when`, maps at every key, a history's sums, refusals; k-step laws (two fitting adds, a reset then at most one amount, refusals); and soundness fuzz: random machines and step laws (and 2- and 3-step laws), every one the kernel accepts holds on every interpreter run (every run of k steps from every reached state), and false ones are caught |
| `history.test.ts` | Random machines with a history (and ceiling-shaped ones that need their relation): every law the kernel accepts holds on every run of the interpreter, which keeps the log, and so do the relations; histories outside the rule are refused |
| `probe-field-param.ts` | The counterexample Lean's proof exposed (a param named like a record field, r.t): now refused |
| `probe-products.ts` | Twelve true nonlinear laws (x² + y² ≥ 2xy, x ≤ y ⇒ x³ ≤ y³, …) proven, two false ones refuted with true arithmetic |

```sh
bun run-kernel.ts && bun run-more.ts && bun run-progress.ts && bun test kernel.test.ts history.test.ts steplaw.test.ts
```
